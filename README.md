# Affinity Java SDK

[Proposed SDK guide](docs/guide.md) · Review the next interface for practice keys, platforms, patient records, and order signing. These examples are not implemented yet.

Server-side client for the Affinity API, version `2026-09-28`. Requires JDK 17+ and Maven.

## Install

```sh
git clone https://github.com/affinity-health/affinity-java.git
cd affinity-java
mvn install
```

## Use

Set `AFFINITY_API_KEY` to a Test key in your server environment. Never put API keys in browser or mobile code.

The build installs `io.github.affinity-health:affinity-java:0.2.0` into your local Maven repository. These are local coordinates; the package is not on Maven Central.

```java
import com.affinity.api.AffinityClient;
import com.affinity.api.resources.orders.requests.ListOrdersRequest;

var api = AffinityClient.builder()
    .apiKey(System.getenv("AFFINITY_API_KEY"))
    .affinityVersion("2026-09-28")
    .build();
var orders = api.orders().list(ListOrdersRequest.builder().build());
```

See [the API reference](reference.md) for resource methods and request options. The client defaults to the production API host; a Test key selects Test mode. Use a stable idempotency key for each logical write and reuse it on retry. List responses expose `hasMore`; pass the last resource ID as `startingAfter` to request another page.

## Verify

```sh
mvn test package
```

Tests use local mock transports. Generated by Cloudflare Forge and Fern; pinned versions and the source contract hash are in [generation.json](generation.json).

## Guide

Read the [Java guide](https://docs.joinaffinityai.com/guides/reference/sdks/java/) for patients, catalog items, writes, pagination, and errors.

Version 0.2.0 defaults to API `2026-09-28`, no automatic retries, and a 60-second timeout.
Explicit client and request options override these defaults. Custom HTTP transports manage their own timeout support.
